# docs

| Folder / file | What |
|---|---|
| [`plans/`](plans/) | Roadmaps and milestone plans — *what* we build and in which order |
| [`specs/`](specs/) | Detailed designs of one feature or contract — *how* it works |
| [`adr/`](adr/) | Architecture Decision Records — *why* we chose one option over others |
| [`issues/`](issues/) | How to report bugs, request features, and how issues are triaged |
| [`CONTRIBUTING.md`](CONTRIBUTING.md) | How to contribute code and docs |
| [`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md) | Community standards |
| [`SECURITY.md`](SECURITY.md) | How to report a vulnerability |

Rule of thumb: a plan says *we will build X in M2*; a spec says *X has these fields and this
behaviour*; an ADR says *we chose Postgres over ClickHouse because…*.
